# Ranked findings

**1. HIGH — `src/labloop/runner.py:53` — the `PYTHONPYCACHEPREFIX` mirror reopens the .pyc forgery hole, outside the digest.**
The prefix mirror (`/tmp/labloop-pycache/<abspath-of-workdir>/...`) is (a) **not under any protected pattern**, so the harness digest never sees it, and (b) **read by the measurement child**, which inherits the same prefix. A proposer can plant a crafted `.pyc` there with the honest source's mtime/size in its header, and the run command executes forged bytecode while the protected source stays byte-identical. Counterexample (reproduced end-to-end, `/tmp/forge_pyc.py`): protected `evals/` with `VALUE = 0.5`, incumbent 0.5; proposer compiles `VALUE = 0.0001`, patches the 16-byte pyc header, writes it to the mirror path (readable from its own inherited env), plus a benign `train.py` edit. Result: **trial KEPT, metric 0.0001 committed, source unchanged, digest unmoved, zero in-tree `__pycache__`.** On `main` the same attack must plant in-tree, which the digest catches; the fix actively moves the forgery surface out of the digested area. Secondary: the fixed, predictable, shared `/tmp/labloop-pycache` path is also a cross-user `/tmp` hazard (symlink/pre-plant attacks) and is never cleaned (unbounded growth). Smallest fix: when injecting the default, use a **fresh `tempfile.mkdtemp` per `run_command` invocation, removed in `finally`** — the propose child's plant dies with its prefix dir, the measure child recompiles from true source, and the shared predictable path disappears (~4 lines). Residual: a caller-*supplied* persistent prefix still leaves the mirror outside the digest — document that in the docstring.

**2. MODERATE — `src/labloop/loop.py:181` — wait-mode `require_clean()` runs before the first lock acquisition; a run can start a trial on a dirty tree.**
In `--wait` mode `_run` checks the tree *once*, outside the lock, then queues. A peer that dies (SIGKILL) or is Ctrl-C'd mid-trial — a state the new code explicitly produces and records as INTERRUPTED, tree deliberately left dirty — releases the lock via the OS; the queued run then acquires it and proceeds on the dirty tree. Counterexample (reproduced, `/tmp/wait_dirty.py`): baseline clean, peer's unjudged file appears at lock-acquisition time → `main`: `DirtyTreeError` (refused); **branch: trial runs, `revert()` deletes the peer's unjudged work** (a kept trial would silently absorb it into the "improvement" commit via `changed_paths()`). Smallest fix: move `require_clean()` inside the per-trial `with self.lock:` block (first statement) — one-line move; the no-wait path is unaffected (already under the whole-run lock, and the loop already runs `git status` several times per trial).

**3. MODERATE — `src/labloop/cli.py:555-556` — `log --json` stamps every trial with the *last* manifest's label, violating its own stated contract.**
The comment says "each trial carries the label of the spec in force", but the code reads only `last_manifest()`. Counterexample (reproduced, `/tmp/label.py`): `baseline --label gpt-5` then `run --label claude` → trial 0 reports `"label": "claude"`. Worse for the primary use case (A/B-ing proposers): a pre-label ledger plus one labeled run reports the new label on *all* historical trials (`index=0` pre-label → `'new-model'`). Provenance reporting is the feature's whole point, and it misattributes exactly when labels change. Smallest fix: walk the raw ledger records in file order, tracking the manifest label in force, and stamp each trial as emitted (a ~10-line `Ledger` helper yielding `(trial, label)`; manifests and trials already interleave in one file).

**4. LOW — `src/labloop/runner.py:53` — an ambient `PYTHONPYCACHEPREFIX=""` silently disables the protection.**
`setdefault` sees the key as present and keeps `""`; CPython treats an empty value as unset (`sys.pycache_prefix is None`), so children write in-tree `.pyc` and the digest moves — recreating the false `harness_changed`/`HarnessMismatchError` this fix exists to kill (reproduced: my first forge run failed with a digest mismatch for exactly this reason). Smallest fix: inject when `not merged_env.get("PYTHONPYCACHEPREFIX")` instead of `setdefault`.

**5. INFO (pre-existing, not a regression) — staged renames (`git mv`) still break `commit()`.** `git add -A -- <old-path>` pathspec-errors after `git mv` stages the rename; reproduced on **both** `main` (which also mangles paths to `sub/sub/`) and the branch. The loop degrades gracefully (`FAILED`, "could not be committed", revert), so cosmetic. Also INFO: a symlinked workdir shows the untracked symlink itself in `changed_paths()` — faithful report; `require_clean` refuses either way, same as `main`.
